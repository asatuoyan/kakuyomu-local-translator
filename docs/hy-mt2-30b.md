# 腾讯 Hy-MT2-30B-A3B 专用适配

参考：[官方模型卡](https://huggingface.co/tencent/Hy-MT2-30B-A3B)、
[官方 GGUF](https://huggingface.co/tencent/Hy-MT2-30B-A3B-GGUF)。

名称包含 Hy-MT2 和 30B 的模型自动启用此配置，包括本机
`hy-mt2-30b:latest` 与官方 Hugging Face Ollama 地址。
本机 `/api/show` 已确认该别名对应 `Hy-MT2-30B-A3B-Q4_K_M.gguf`。

使用单条 user 消息，不添加 system；语言使用中文全称。
术语以“原词 翻译成 译词”注入，前批译文使用背景信息区，
长度受 `min(context_chars, hy_mt_context_chars)` 限制，默认最多 256 字。
单段 80 字以内不附背景，是本程序对独立标题的启发式处理。
维持段落数量校验、异常长度保护、自动拆批及断点续译。

官方 30B-A3B 建议温度 0.7、top_p 1.0、top_k -1（不截断）、
重复惩罚 1.0、最多 4096 生成 token；与官方 7B 建议不同。
Ollama/llama.cpp 侧用 top_k=0 表示关闭，repeat_penalty=1.0、num_predict=4096；
min_p=0.0 避免引入额外采样筛选，think=False 保持直接译文调用。
超限单段重试提高重复惩罚到 1.05，属于本程序恢复策略。

本机导入参数为 num_ctx=4096，而 GGUF 元数据声明 context_length=262144。
元数据上限不代表当前运行窗口。请求窗口显式使用 `hy_mt_num_ctx`，默认 4096；
可配置为 8192，但扩大窗口可能触发重新加载并增加内存占用。
分批按同一个请求窗口估算，不采用 Murasaki 的 1536 字上限。
单个超长段落仍可能超过分批目标。

## 2026-10-05 速度调整

默认 `hy_mt_prefer_whole_chapter=true`。当当前章剩余待译段落能同时满足
用户字数上限、段落上限、上下文估算及输出预算时，一次提交全部段落；
否则继续自适应分批。不会为了整章而接受截断或错位结果。
关闭该选项可恢复按初始目标分批。

混元预算改为 `(请求窗口 - 512 - 参考字数 × 2) // 4`，
并按 4096 输出 token 预留 256，再用每字两 token 保守估算，批次最多 1920 字。
此处均为工程估算，不能保证任意语言的精确 token 数。
默认 4096 窗口、256 字参考内容时，允许约 768 字，旧算法在 1200 字参考时约 236 字。
仍保留 `translation_chunk_chars` 和 `translation_chunk_paragraphs` 的用户上限。

修正排版指令位置：旧提示词在翻译指令冒号后放排版要求，实测混元将其当作原文输出，
导致额外一段并触发拆批。现在排版要求放在翻译指令之前。

本机 Q4_K_M、4096 窗口，680 字/5 段合成日文样本：
旧实现 3 次请求约 30.08 秒；修改后 1 次请求约 9.94 秒，段落数量正确。
这是单次端到端样本，不能保证所有小说有相同加速或翻译质量。
8192 窗口试验出现 15–31 秒加载时间，服务随后又显示 4096，因此没有默认扩大窗口。
在项目根目录运行 `python -X utf8 -m scripts.bench_hy_mt --sizes 5 10` 可复测，分别记录加载、输入处理和生成耗时。

## 独立术语模型

可在 config.json 设置 `"glossary_model": "qwen3.8:27b"`（本机已安装的模型名）。
“术语管理”的 AI 扫描使用该模型，候选词仍需审核后加入术语表；
留空则使用翻译模型。不会自动扫描整书或在翻译任务启动前强制扫描。

新请求使用独立批次缓存标识，已完成项目章节继续保留。
