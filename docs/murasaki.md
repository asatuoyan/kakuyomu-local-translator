# Murasaki 调用适配（2026-10-04）

当前本机模型为 `murasaki-8b-q6:latest`，Ollama 显示 GGUF 为
`Murasaki-8B-v0.2-Q6_K.gguf`、8.2B、Q6_K，导入参数 `num_ctx=16384`。
这是本机运行配置，不代表模型原生上下文上限。未能直接读取 8B 模型卡，
因此不把 14B 模型卡的参数当作已经验证的 8B 硬限制。

## 参考来源与能力范围

- [官方前端 README](https://github.com/soundstarrain/Murasaki-Translator/blob/main/README.md)：
  模型侧重 ACGN 段落翻译，原生使用 CoT；上下文包含提示词、术语表、思考和译文。
  推荐批次 512–3072，平衡区间 1024–1536；这是前端建议值，不是模型硬上限。
  8B 显存参考最低 6 GB、推荐 8 GB+，不能据此保证 Q6_K 和较长上下文完全驻留显存。
  README 的约 200 字/秒来自 RTX 4080 Laptop、4-bit、四并发，且包含思考输出，
  不可直接与本程序单任务 Q6_K 的纯译文速度比较。
- [官方模型项目](https://github.com/soundstarrain/murasaki-project)：
  v0.2 为 8B/14B 推理模型，多模式提示词覆盖正文、剧本和短句；
  项目将非思考能力迁移列在 4B v0.3 版本，不能假定关闭 v0.2 思考等价于官方快模式。
- [作者维护的评测](https://github.com/soundstarrain/Murasaki-benchmark)：
  验证范围为日文到中文 ACGN 段落，短样本约 180–200 字、长样本约 780–800 字。
  不能由此推断模型支持所有语言或十几个字标题具有同样表现。
- [14B v0.2 模型卡镜像](https://dev.modelhub.org.cn/Murasaki-Project/Murasaki-14B-v0.2)：
  展示 system/user 分离、术语表放在 system、用户输入“请翻译”、思考与译文分离；
  采样温度推荐 0.3，重复惩罚可从 1.0 提升至 1.05–1.1。
  此处借鉴调用结构，不声称已验证 8B 与 14B 全部参数相同。

## 本程序实现

`murasaki_profile.py` 仅为名称包含 Murasaki 8B/14B 的中文任务启用专用配置。
正文使用小说提示词，单段不超过 80 字时按独立短句处理（本程序启发式规则）。
术语表放在 system，user 只放待译原文，不附加上一批中文译文，减少复制和续写风险。
其他语言仍走通用路径，其质量未由上述日中评测验证。

`murasaki_thinking_mode` 默认为 `auto`：80 字以内单段直接翻译，正文启用简短思考。
可在 config.json 设为 `off` 全部直接翻译，或 `on` 全部开启思考。
直接翻译至少预留 256、思考请求至少预留 4096 个生成 token，随原文长度增加。
思考字符预算为 `min(4096, max(1024, 原文字数 × 2))`，只针对 Ollama 独立的
`message.thinking` 字段。超预算关闭该请求，不保存部分结果，改用直接翻译重试；
这不是精确 token 预算，也不是强制结束思考并在原请求中续生成。
旧导入模板将思考混在 content 时，只受总输出长度保护。
关闭思考属于本程序的效率策略，v0.2 模型的非思考质量没有官方保证。
温度 0.3、重复惩罚 1.05；超限重试时分别提高到 0.5 和 1.1。
译文依旧有长度保护和段落校验；`<think>` 内容不会写进 EPUB，未结束思考视为失败。
正文批次上限为 1536 字，实际还受现有自适应分批和上下文估算约束。
单次超长段落仍可能超过批次目标。

新提示词使用独立的批次缓存标识，已完成的项目章节仍可续用。
此改动改善调用匹配与异常控制，不保证质量提高或固定加速倍数。
排查速度应分别记录模型加载耗时、提示词处理耗时、思考 token、译文 token 和 GPU 驻留情况。
