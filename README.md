# 小说 EPUB 获取与本机翻译工具

[English instructions](README.en.md)

支持 Kakuyomu（カクヨム）和小说家になろう（Syosetu）的原文获取，以及通过本机 Ollama 翻译 EPUB。下载、导入、翻译、术语管理和局部重译可在 GUI 或 CLI 中使用。

默认配置下，正文只在你的电脑、小说网站和本机 Ollama 之间流转。修改 `ollama_url` 为远程地址后，正文会发送至该地址。

## 安装与启动

需要 Windows 10/11、Python 3.11 和 Ollama。模型需要额外的磁盘空间和内存；翻译时建议关闭占用显存较多的软件。

1. 安装 Python 和 Ollama。
2. 在终端安装一个模型（默认使用 Q4_K_M）：

   ```powershell
   ollama pull hf.co/tencent/Hy-MT2-7B-GGUF:Q4_K_M
   # 显存充足时也可选择：
   ollama pull hf.co/tencent/Hy-MT2-7B-GGUF:Q6_K
   ```

3. 双击 `run_web.bat` 打开本地 Web 版，或使用 `run_gui.bat` 打开 GUI、`run.bat` 打开 CLI。

### 本地 Web 版

Web 版只保留“获取并翻译”和“术语”两个页面。启动后自动打开浏览器；输入 Kakuyomu / Syosetu 作品网址，选择翻译模型，点击“获取并翻译”。第一章获取完成后立即开始翻译，同时继续获取后续章节，无需试译和确认全书。翻译按原文章节顺序进行，每章保存首次译名后供后续章节沿用。也可展开设置填写本地 EPUB 路径和选择输出语言。页面分别显示已获取、已翻译章数；已有项目列在“我的作品”中，可直接阅读已保存章节。

获取与翻译各自保存进度：原文和图片写入获取缓存，译文按章保存到翻译项目。点击“停止”后等待任务显示已停止，可从网址旁的“最近使用的小说”下拉框（显示书名和网址）再次启动，复用获取缓存并跳过已完成译文。获取线程保持网站请求间隔，通过最多 3 个待处理消息的队列与翻译线程衔接，避免无限堆积。完整获取、翻译和术语保存全部完成后生成全文 EPUB；失败或停止时保留已获取缓存和已译章节，不导出未完成的全书。

翻译模型下拉框自动读取当前 `ollama_url` 中已安装的模型，优先选中已安装的配置模型，否则选择列表中的第一个。安装新模型后点击“刷新模型”。没有模型或连接失败时不能开始任务；开始前也会核对模型是否存在。任务运行时锁定模型选择。

每章保存后，程序调用 `glossary_model`（未设置时使用翻译模型），从原文和对应译文提取专有名词。只接受原文存在且译名出现在该原词首次出现段落的条目，自动保存至作品的 `glossary.json`，供后续章节使用。已有术语不会被自动覆盖；AI 提取仍可能遗漏或错配，术语页可直接修改。提取结果格式异常时停止任务，已译章节保留，再次启动可继续提取和翻译。

术语提取使用 `glossary_num_ctx` 指定请求上下文（默认 8192），并预留提示词和 JSON 输出空间；较长输入会分批，超长段落使用有重叠的文本窗口。此参数与翻译的 `hy_mt_num_ctx` 独立。增大上下文会增加内存／显存占用，需在模型支持范围内调整。HTTP 错误会显示 Ollama 返回的具体原因，例如输入 tokens 超出上下文。

术语页支持 JSON 导出、导入和自动保存导入结果，可将文件交给其他 AI 统一译名，保留 `source`（原词）、`target`（译名）字段后导入。同名原词更新译名；直接编辑后点击“保存修改”。翻译运行时需先停止任务再修改或导入术语，再次启动使用更新的译名。术语修改不会重写已保存译文。首次译名固定以章节为单位，同章内仍可能出现不同译名。

服务仅监听本机地址，不需部署。关闭启动终端窗口即可退出；浏览器标签关闭后任务仍继续运行。也可运行 `.venv\Scripts\python.exe -X utf8 web_app.py --no-browser --port 8765`，使用终端打印的地址打开页面。

首次启动会创建 `.venv` 并安装依赖；以后仅在 `requirements.txt` 或解释器文件变化时重新检查安装。普通启动不执行 pip，也不安装浏览器。需要手动重新检查依赖时运行 `run_gui.bat -Update` 或 `run.bat -Update`。

GUI 默认以简体中文显示。顶部“当前功能 ▾”菜单提供“获取小说”“翻译小说”“检查译文”三个入口；获取小说页可切换网络下载和本地导入，翻译页可进入术语管理。选中作品后顶部中间显示书名，右侧设置可调整模型、Ollama 地址和主题；运行日志可从底部状态栏展开。在支持的 Windows 版本上，窗口标题栏也会随主题切换。新建翻译任务默认勾选简体中文。已有 `config.json` 中的 `target_language` 设置仍用于 CLI 和相关项目流程，可按需自行修改。

`config.example.json` 提供默认设置；首次启动会生成 `config.json`。应用会补齐旧配置缺少的字段并检查常用数值和连接地址。GUI 与 CLI 保存设置时只更新改动的字段，保留其他设置和相对路径。

网页模式默认使用已安装的 Microsoft Edge，也可选择 Chrome、自定义 Chromium 或 Playwright Chromium。仅首次选择尚未安装的 Playwright Chromium 时下载浏览器；只翻译本地 EPUB 不需要下载浏览器。

CLI 在模型缺失时可询问是否下载；GUI 请先用上述命令安装模型。

## 功能与使用流程

### 1. 网站 → 日文 EPUB

**从网址一键获取并翻译：** GUI“网络下载”页输入作品网址，在底部选择模型和“先试译前 N 章”（默认 20），点击“一键获取并试译”。程序自动读取目录，仅获取指定范围的原文，再接续翻译、检查和网页阅读；不用先手动下载 EPUB 或重新选择文件。需要登录时请在打开的浏览器中完成登录。

试译结束后会等待你的确认。点击网络下载页的“确认后获取并翻译全部”，或翻译页的“确认后翻译全部”，即可自动获取剩余原文并继续翻译。已获取章节复用缓存，已翻译章节复用项目；若原文章节顺序或已译内容改变，会报告错误并停止。暂停或失败时保留已获取缓存，可用相同网址重新启动。网络流程状态保存在输出目录的 `network-workflows/` 中。

支持：

- `https://kakuyomu.jp/works/...`
- `https://ncode.syosetu.com/.../`
- `https://novel18.syosetu.com/.../`

CLI 选择菜单 1，或使用 GUI 下载页。输入作品网址，在程序打开的独立浏览器中完成登录，再读取目录并选择章节范围，例如 `21-40`（包含首尾）。

程序保存正文、章节目录、插图、作品简介和网页提供的官方封面。每章下载后写入 `source-cache.json`；中断后选择相同范围会跳过已缓存章节。缓存用于续传，不会自动重新请求所有已下载章节以检查网站更新。

Kakuyomu 目录从作品页内嵌的完整分卷数据读取，不依赖当前展开的卷。目录可列出不代表当前账号可以读取正文，实际访问范围以账号权限为准。

默认章节请求间隔约 9–12 秒，插图请求另有间隔。可通过 `request_delay_seconds` 增加等待时间；程序保留至少 8 秒的章节请求间隔。临时网络错误可退避重试；检测到网站访问封锁时停止下载。

### 2. 日文 EPUB → 多语言 EPUB

**GUI 默认采用“先试译，再确认全书”的流程：**

1. 选择原文 EPUB、模型和输出语言，设置“先试译前 N 章”（默认 20，可增加或减少）。点击“一键试译”即可翻译指定范围，自动生成试译 EPUB、术语候选和检查报告，并打开网页阅读。少于 N 章的小说只处理实际章节。
2. 试译结束后程序停在等待确认阶段，不会自动翻译后面的章节。点击“固定术语”审核候选、填写并保存译名；未确认的候选不自动加入术语表。点击“检查 / 局部重译”进入对应项目检查页，可以定位问题并重译选中段落。
3. 确认试译质量和术语后，点击“确认后翻译全部”，接续翻译剩余章节，复用已有译文。完成后自动检查并打开阅读。已完成章节不会因修改术语而自动全部重译，需要更新旧译名时请执行局部重译。

试译与全书使用同一个可续译项目，试译 EPUB 文件名带 `_试译_0001-NNNN`，不会覆盖全书 EPUB。工作流进度保存在输出目录的 `workflows/` 中，重启后选择相同原文和语言即可继续。更换原文内容或增加尚未试译的语言时，需要先完成相应试译；全书任务会核对原文。当前按原文章节顺序推进，网页分卷显示仍取决于目录可识别的卷名标记。CLI 菜单 2 仍按原有方式翻译全书。

CLI 菜单 2 或 GUI 翻译页支持多选繁体中文、简体中文、英文、日文、韩文、法文、德文和西班牙文，各语言依序翻译并生成独立 EPUB。

GUI 翻译页底部固定显示“翻译进度”区域，“一键试译”和“确认后翻译全部”按钮位于该区域右上角。区域包含总进度百分比、进度条、当前语言、章节和段落进度；每完成一批段落更新一次，缓存和续译也计入进度。生成 EPUB 完成后显示 100%。修改程序后请关闭旧窗口，再通过 `run_gui.bat` 重新启动。

模型生成期间，状态显示当前批次、输入字数、等待秒数和已生成字数；模型返回思考内容时显示“模型思考中”。百分比只计入已完成并通过完整性检查的批次，因此等待第一批时可能暂时停在 0%。长篇小说按章节和批次处理，不会一次提交整本小说；`translation_chunk_chars` 是分批目标，单个超长段落仍可能超过该值。多段批次遇到输出长度限制时会自动拆小重试。

默认启用自适应分批（`adaptive_translation_batches: true`）：从最多 800 字、8 段起步，连续两批在 30 秒内完成且无需降级后逐步增加；出现重复、段落不匹配、重试或单批超过 45 秒时缩小下一批。最大字数和段数仍受 `translation_chunk_chars` / `translation_chunk_paragraphs` 限制。程序尝试读取已加载模型的实际上下文容量，读取不到时按 4096 token 保守估算，并为提示词、术语、前文及译文预留空间。token 预算为估算，单个超长段落不强行拆断。日志显示动态选定的段数和字数；设为 `false` 可恢复固定分批。自适应调整不能保证语义翻译准确。

勾选进度区域中的“双语对照输出”，可在同一个 EPUB 中逐段显示原文和译文：原文在前，译文在后，插图保持原有顺序。原文不做简繁转换，译文通过缩进和左侧细线区分。文件名带 `_双语对照`，不会覆盖纯译文 EPUB；已完成的翻译可直接复用，无需重新调用模型。多选语言时，每种语言各生成一本“原文 + 该语言译文”的对照 EPUB。CLI 菜单 2 可通过 `config.json` 中的 `"bilingual_output": true` 启用。此选项用于章节正文，作品简介和目录标题仍显示译文。

- GUI 翻译时可点击“实时阅读”，每批完成后自动显示译文，支持原文 / 译文对照和切换章节；更新时保留阅读位置。中止后已显示的内容仍可阅读，重新开始会从缓存恢复。阅读窗口当前显示正文文字，插图保留在最终 EPUB 中。
- 点击“网页 / 手机阅读”即可在电脑浏览器阅读，并查看手机访问地址。手机与电脑连接同一 Wi-Fi，在手机浏览器打开显示的局域网地址；如无法连接，请允许 Python 通过 Windows 防火墙的专用网络。网页每两秒检查新译文，提供章节目录、原文对照、字号和夜间模式，并在当前浏览器保存阅读位置。点击“目录”展开侧边栏，可按语言和卷浏览章节；卷内章节可折叠，侧栏可随时收起，手机选择章节后自动收起。分卷依据章节标题中的“第 X 卷／巻／部”标记，后续章节沿用该卷；没有标记的章节显示在“未分卷”中。正文底部提供上一章／下一章。保持电脑程序运行即可持续阅读，无需上传小说；关闭程序后服务停止，下次打开需使用新地址。网页目前显示正文文字。
- 整书翻译不再自动生成分册，全部完成后输出完整 EPUB；批次和章节仍持续保存，可中断续译。
- 各语言的项目、缓存和术语表独立保存在 `output/<原文文件名>_翻譯/<语言代码>/`。匹配原文和语言的旧中文项目继续使用原目录。
- 已完成章节可以续传；切换模型不会自动重译已经完成的章节。
- 原 EPUB 仅追加章节，且已完成章节的 URL 与正文逐章匹配时，可在原项目继续翻译；已有章节被修改、删除或重排时会停止并提示核对。
- 中文标题、简介和正文通过 OpenCC 统一简繁，此选项不改变 GUI 界面语言。
- GUI 中某种语言失败后会继续处理其他语言，并汇总成功结果和错误；点击“中止”会停止剩余任务。

EPUB 导入支持段落、普通容器、列表、引用、子标题、换行、图文混排和纯图片章节。插图按 XHTML 相对路径解析，保留不同目录的同名图片；找不到引用的图片时报告错误。翻译输出会重新排版，不保证保留输入 EPUB 的全部 CSS、字体或交互内容。

翻译完成后或重启程序后，可在 GUI 翻译页点击“打开已完成小说”，选择输出的译文 `.epub`，或项目目录中的 `translation-project.json` / `project.json`，直接进入网页／手机阅读，无需重新翻译，也无需启动 Ollama。项目保存了原文时支持原文对照；旧项目缺少原文时仍可阅读译文。EPUB 按文件中的正文展示，双语 EPUB 保留已有双语正文。阅读期间保持程序运行，手机访问方式与上方说明相同；当前网页阅读显示文字，插图请使用 EPUB 阅读器查看。

已完成小说的目录在后台加载，正文按章读取，最近阅读的 8 章保留在内存中。EPUB 打开时只读取书籍目录，不提取图片；新版分章项目首次建立目录后，会在本机用户缓存目录保存索引，源文件变化后自动重建。旧版整份 JSON 项目首次仍需读取完整 JSON。上述缓存不修改小说或项目文件。

### 3. 追加到已有中文 EPUB

CLI 菜单 3 中先选择日文 EPUB，再选择中文母版。母版不会被覆盖，其原有内容和资源保留，新译章节追加到目录及阅读顺序末尾。程序自动检测母版主要使用简体还是繁体。

请选择仅包含尚未收录章节的日文 EPUB；程序不会推测它与母版章节的对应关系。

### 4. 手动网页单章续接

CLI 菜单 4–5 适合临时翻译一章或续接旧项目。在浏览器打开章节后回到命令窗口按 Enter；输入 `m` 切换模型，输入 `q` 安全结束。每累计 10 章重建一次 EPUB，退出时补写未打包结果。

### 5. TXT / Markdown / UMD / JAR 导入

CLI 菜单 7 或 GUI 导入页支持单文件和文件夹批量导入：

- TXT、Markdown 根据第 X 章/话/回、Chapter、Markdown 标题等规则切分章节。
- 文件夹按自然顺序排列，支持阿拉伯数字、全角数字和中日文章节数字。
- UMD、Java ME JAR 可提取支持格式的书名、作者、目录、正文和封面。
- 自动识别常见编码，包括 UTF-8、UTF-16、CP932、GB18030 和 Big5。
- 自动判断简体中文、繁体中文或日文，支持 Markdown 本地图片。
- 可打包 EPUB，或将已有中文内容导入可编辑项目。中文导入项目没有日文原文时，术语检查只能基于实际保存的文本进行，不能评估日文翻译准确性。

CLI 菜单 8 可打开 GUI。

## 翻译模型、完整性与中止

翻译提示词参考 [腾讯 Hy-MT2 官方模板](https://huggingface.co/tencent/Hy-MT2-7B#hy-mt2-translation-task-instruction-examples-chinese-english-comparison)，将术语参考、背景信息和待翻译原文明确分开，要求只输出小说译文并保持段落对应。检测到翻译指令或输入标签混入输出时，会移除前文参考并逐段重试；仍异常则报告失败，不保存该批次。读取翻译缓存时也会跳过包含此类指令的结果。已经保存为完成章节或导出的 EPUB 不会自动重写，发现旧译文污染时请在“检查译文”中对相应段落执行局部重译。

内置以下两个推荐模型。GUI 设置页可读取当前 Ollama 地址上的已安装模型，设置页和翻译页均通过下拉框选择模型；翻译页会使用所选模型。模型必须已安装在对应 Ollama 服务中。

GUI 启动时自动读取 Ollama 已安装模型，下拉框只显示实际存在的模型。优先选择已安装的配置模型，否则选择列表中的第一个；没有模型或连接失败时保持为空。安装模型后，可在设置页点击“刷新模型”，无需重启。

底部“运行日志”打开独立日志窗口，不挤压翻译页。窗口显示批次、重试和错误输出；在底部时跟随新日志，向上滚动查阅时保持位置。日志为只读，可选择复制；文件路径和原始输出保留原样。

界面状态文字统一使用简体显示；“繁体中文”表示目标语言，不表示界面切换为繁体。勾选多个目标语言时依次完成整本翻译，不会逐章交替切换语言。

| 选项 | Ollama 模型名 |
|---|---|
| Hy-MT2 7B Q4_K_M（默认） | `hf.co/tencent/Hy-MT2-7B-GGUF:Q4_K_M` |
| Hy-MT2 7B Q6_K | `hf.co/tencent/Hy-MT2-7B-GGUF:Q6_K` |

来源：[腾讯官方 GGUF 仓库](https://huggingface.co/tencent/Hy-MT2-7B-GGUF)。未设置模型时默认使用 Q4_K_M；旧翻译模式和校对设置不再生效，已有译文保留。

### 使用已部署的 Ollama 本地模型

已有模型时可跳过安装步骤，直接将其作为翻译和术语扫描使用的模型：

1. 启动 Ollama，运行 `ollama list` 查看已部署模型的完整名称（含标签）。
2. GUI：打开右上角设置，确认 Ollama 地址（默认 `http://127.0.0.1:11434`），点击“刷新模型”，从下拉框选择已安装模型并保存；翻译页的模型下拉框同步更新，可直接切换模型。
3. CLI：在模型选择菜单选择“选择 Ollama 已部署的本地模型”，再按编号选择；或选择“手动输入 Ollama 模型名称”。已部署模型直接使用，无需再次下载。

也可在 `config.json` 中设置以下字段，保留其他配置：

```json
{
  "ollama_url": "http://127.0.0.1:11434",
  "model": "my-translator:latest"
}
```

将 `my-translator:latest` 替换为你的实际模型名称。模型列表来自配置地址对应的 Ollama 服务；选择支持文本对话和目标语言翻译的模型。切换模型后，已完成章节仍会跳过，需要重译时使用局部重译功能。

翻译使用简短指令和纯文本输出，不要求 JSON，也不进行二次校对。多段原文以空行分隔；返回段落数不匹配时拆分重试。术语表和前文仅在有内容时加入参考。

翻译请求设置 `think: false`，关闭支持此开关的模型的思考模式，直接生成译文。状态中的“模型思考中 · N 字”指思考内容，不代表已翻译 N 字；若旧窗口一直显示大量思考内容，请停止任务、关闭窗口并重启，再开始续译。

前文参考和待译正文通过独立标签分隔；发现明显复制前文或不同原文产生相同长译文时，会移除译文参考并逐段重试。此检查只能识别部分重复，不能保证模型翻译准确。已完成章节不会自动重译，发现旧译文有误时可在“检查译文”中选择段落重译。想尝试整章输入，可提高 `translation_chunk_chars` 和 `translation_chunk_paragraphs` 使章节落在同一批次，但需为提示词、前文和输出预留模型上下文空间；更大批次不保证质量更好。

流式响应必须收到完成标记才视为成功。提前结束、无效响应或长度限制导致的不完整结果不会写入缓存。段落数量一致仍不能保证语义上没有漏译，重要内容应人工核对。

连接中断、超时和暂时性模型错误默认最多重试 5 次，等待 10、20、40、60、60 秒。已完成批次保留。配置项：

| 配置 | 用途 |
|---|---|
| `translation_chunk_chars` / `translation_chunk_paragraphs` | 每批字符数 / 段落数 |
| `context_chars` | 前文参考长度 |
| `translation_max_retries` | 最大重试次数，0 表示关闭 |
| `translation_retry_delay_seconds` | 第一次重试等待秒数 |
| `request_timeout_seconds` | 网络请求超时 |

GUI 的“中止”适用于整书翻译和局部重译，也可取消重试等待或正在等待模型响应的任务。已完成批次/章节保留，迟到的响应不会写入项目。底层网络读取可能要等到下一个响应或超时才释放；本地 Ollama 可能短暂继续处理已取消的请求。再次开始会创建独立的取消状态。

## 术语管理、稽核与局部重译

- 每个作品/语言目录可保存 `glossary.json`，同名条目优先于全局设置。
- 全局 `glossary` 用于中文；其他语言使用 `glossary_by_language`，例如 `{"en": {"竜": "dragon"}}`，或该语言项目的术语表。
- 支持快速候选词提取，以及使用本机模型扫描人物、地名、组织、技能、魔法、称号和特殊设定。
- 支持候选词审核，以及 CSV、Excel `.xlsx`、JSON 导入导出。JSON 可使用条目数组、分类对象或原文到译名的字典。
- 翻译期间可检查术语是否落实；项目稽核会列出对应章节和段落。
- GUI 稽核页也会提示空译文、与原文相同的译文，以及长度明显异常的段落。这些是人工核对线索，不代表程序已确认漏译或误译。

**修改术语后的推荐流程：**保存术语表 → 在“译文检查”页选择项目并开始检查 → 在问题详情中重译选中段落，或从“更多操作”输入指定术语、勾选“全部术语”并执行范围重译。问题的“已处理／已忽略”状态保存在项目的 `audit-status.json` 中。

局部重译仅调用模型处理命中的正文段落，保留其他段落和图片，并重建输出。整书翻译项目的全书和分册都会更新；追加项目保留母版。若中途取消，已完成章节已保存，再次执行局部重译可更新 EPUB。不需要手动删除缓存。

稽核和局部重译同时支持 `project.json` 与 `translation-project.json`。旧翻译项目若没有保存原文，会提示选择创建项目时的原始 EPUB；校验文件和章节内容匹配后补齐对应关系。无法恢复原文或段落不对齐时会报告错误，不会把未检查的内容显示为“通过”。

## 项目存储、升级与备份

| 文件或目录 | 内容 |
|---|---|
| `translation-project.json` | 新版翻译项目清单、来源、语言和进度 |
| `chapters/000001.json` 等 | 原文、译文、图片引用和章节信息，按章原子写入 |
| `translation-cache.sqlite3` | 按批次事务提交的翻译缓存 |
| `translation-project.legacy.json` | 旧版整份 JSON 项目迁移时保留的备份 |
| `project.json` | 原有追加/文本导入项目，继续兼容 |
| `source-cache.json` | 下载续传缓存 |
| `assets/`、`source-assets/` | 项目资源；请与项目一起保留 |

新缓存包含模型、语言、术语表、章节身份、原文内容、段落位置和相关翻译设置，避免跨章节复用语境不同的相同对白。旧 `translation-cache.json` 保留，但缺少语境信息，因此不用于新任务的缓存命中；已经保存在项目中的完成章节仍会跳过。仅存于旧缓存、尚未保存为完成章节的内容可能需要重新翻译。

旧翻译项目在写入时迁移为分章格式，保留旧文件备份。备份或移动项目时，请复制整个项目目录，不要只复制清单或 SQLite 文件。进行迁移或批量修改术语前，建议保留目录备份。

## 登录与隐私

每种浏览器使用程序专用的独立配置目录，例如 `browser-profile-msedge`；不会读取日常 Edge 主配置。登录跳转属于正常流程，请在程序窗口完成登录，CLI 中返回作品页后再按 Enter。

GUI 中点击下载页的「登录 Kakuyomu」，在打开的浏览器中手动完成登录，然后关闭该浏览器并点击「读取目录」。登录窗口始终可见，登录状态保存在当前浏览器的程序专用配置目录中；后续使用同一种浏览器即可复用。普通浏览器中的登录状态不会自动同步到程序。

可选 `cookies.json` 接受 Playwright `storage_state` 或 Cookie 数组，并仅导入 Kakuyomu 域名条目。不要分享 Cookie、浏览器配置目录、私人输出或未清理的整个项目目录；这些运行文件已加入 `.gitignore`。

程序只能获取当前账号正常有权打开的章节，不绕过会员、付费或其他访问限制。

## 常见问题

- **网站提示“不正と思われるアクセス”**：停止下载，不要连续刷新；稍后先用普通浏览器确认恢复，再继续。已经下载的章节可从缓存续传。
- **目录不全或登录失效**：确认账号能打开作品，在程序浏览器重新登录并读取目录。
- **Ollama 无法连接**：运行 `ollama serve`，确认 `http://127.0.0.1:11434` 可访问。
- **模型加载失败**：确认安装了所选量化版本；显存不足可用 Q4_K_M。
- **旧项目无法稽核**：选择创建项目时的原始 EPUB；重新下载或重新打包的不同文件可能无法通过匹配校验。
- **EPUB 无法打开或图片缺失**：保留原始 EPUB、项目和错误日志，检查源文件中的图片资源引用。
- **启动依赖异常**：用 `run_gui.bat -Update` 或 `run.bat -Update` 重新检查依赖。
